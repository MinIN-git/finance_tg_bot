# finance_tg_bot

Личный Telegram-бот учета финансов. Данные хранятся в Google Таблице, бот отвечает только
разрешенным Telegram user_id. Python 3.12, aiogram 3, gspread, APScheduler, запуск через Docker Compose
(long polling, домен и открытые порты не нужны).

## Что умеет

| Сообщение | Что запишется |
|---|---|
| `350 кофе` | расход 350, категория «Еда вне дома» (по ключевому слову) |
| `+150000 зп` | доход 150 000, «Зарплата» (слова доходных категорий пишутся доходом и без `+`) |
| `вчера 1200 такси`, `5.10 800 аптека` | с датой (дата без года из будущего = прошлый год) |
| `2000 продукты @наличные` | с конкретного счета (по умолчанию — первый счет в листе «Счета») |
| `50000 Карта -> Вклад` | перевод между счетами (не доход и не расход) |
| `283000 отпуск турция #тяжелое` | **тяжелая трата** (синоним `#крупное`): обычный расход + строка в «Большие покупки» |
| `99,90 молоко`, `1.5к ремонт` | копейки через запятую, `к` = тысячи |

Если категория не угадалась, бот покажет кнопки (с переключателем «это доход») и запомнит слово.
Под записью — «↩️ Отменить», «🏷 Категория» и, если впереди командировка, «✈️ В Казань».

### Отчеты

Правила оформления: суммы без копеек (в итогах — «тыс»), «выше/ниже обычного» и стрелки — только при
отклонении больше 30%, «обычно» — среднее за 3 прошлых полных месяца **без тяжелых трат**.

- `/month` — только текущий месяц: потрачено, из них тяжелые, пришло, «Больше всего» столбцом;
  кнопки «📋 Все категории» и «🕑 Последние траты». `/week` — то же за неделю.
- **Итоги месяца** — приходят 1 числа после опроса остатков по счетам (если до 21:00 не ответить — без
  свежего снимка), по запросу — `/report`: доход, расход и итог без тяжелых трат, капитал на начало месяца,
  категории «выше/ниже обычного», строка о тяжелых тратах. Кнопки: «🧾 Тяжелые траты» (список, как месяц
  выглядит с ними, итог за 12 месяцев) и «📋 Все категории».
- `/stats 3|6|12` (по умолчанию 3; `/quarter` — то же) — картинка с графиками по каждому показателю
  (капитал, доход/расход, крупные категории) и выводы: какие расходы растут и снижаются, как изменился
  капитал. 1 января, апреля, июля и октября приходит сам за 3 месяца.
- `/compare август сентябрь` (или `08.2026 09.2026`) — два месяца рядом; `/cat продукты` — одна категория;
  `/big` — тяжелые траты за 12 месяцев и их доля в расходах.
- `/capital` — капитал по счетам, сверка «не учтено», рост за 1/3/6/12 мес., снимки по месяцам,
  запас прочности; `/snapshot` (или `/деньги`) — записать остатки.
- `/signals on|off` — мягкие напоминания не чаще раза в неделю (категория к 20-му уже больше обычного,
  «Прочее» > 10% расходов, не сошлась сверка капитала).

### Тяжелые траты

Тег `#тяжелое` при вводе: трата записывается в «Операции» и строкой в «Большие покупки» (Дата, Что купил,
Стоимость, Категория, id). Во всех отчетах она считается отдельно и не искажает «обычно». У старых строк
листа без «Категории» сумма вычитается только из общего расхода — впишите категорию, затем `/refresh`.

### Командировки

`/trip Казань 13.10–16.10` заводит поездку (лист «Поездки»). Траты в эти даты помечаются сами (уже
записанные — тоже), купленное заранее (билеты) — кнопкой «✈️ В Казань» под тратой; пометку можно снять.
`/trip` — ближайшая поездка, `/trip cancel` — отменить. `/trips` (или `/командировки`) — все поездки
с днями и суммами, «обычно поездка / в день» и сравнение последней с обычной.
Для прошедшей поездки указывайте год: `/trip Пермь 3.06.2026–5.06.2026`.

Прочее: `/last`, `/undo`, `/categories`, `/refresh`, `/help`. Состояние бота (отправленные итоги, сигналы)
хранится в `data/state.json` (папка `./data` подключена в `docker-compose.yml`).

## Структура таблицы

Бот работает с вашей таблицей и при первом запуске **создает недостающие листы**; существующие листы
(в том числе старые) не трогает.

| Лист | Колонки |
|---|---|
| Операции | Дата, Тип (расход/доход/перевод), Сумма, Категория, Счет, Счет-получатель, Комментарий, Теги, id |
| Счета | Название, Вопрос для ежемесячного снимка (первый счет — счет по умолчанию) |
| Категории | Название, Тип (расход/доход), Ключевые слова (через запятую), Эмодзи |
| Остатки | Дата, Счет, Сумма |
| Большие покупки | Дата, Что купил, Стоимость, Категория, id (колонки «Категория» и «id» бот допишет сам) |
| Поездки | Город, Начало, Конец, id |

Счета и категории (в том числе эмодзи категорий) можно править прямо в таблице, затем `/refresh`.
Колонку «Эмодзи» бот сам добавляет в лист «Категории», созданный старой версией, и больше ее не трогает. Операции, добавленные
вручную, тоже подхватываются (дата — датой или `дд.мм.гггг`, сумма — числом).

## Настройка (один раз)

### 1. Бот в Telegram

1. Напишите [@BotFather](https://t.me/BotFather) → `/newbot` → придумайте имя и username.
2. Скопируйте токен — это `BOT_TOKEN`.

### 2. Ваш user_id

Напишите [@userinfobot](https://t.me/userinfobot) — он ответит числом `Id`. Это `ALLOWED_USER_IDS`
(несколько — через запятую). Также бот пишет в лог `Игнорирую пользователя user_id=...` для всех чужих сообщений.

### 3. Service account Google

1. Откройте [Google Cloud Console](https://console.cloud.google.com/), создайте проект (любое имя).
2. **APIs & Services → Library** → включите **Google Sheets API** (и на всякий случай **Google Drive API**).
3. **APIs & Services → Credentials → Create credentials → Service account**, имя любое, роли не нужны.
4. Откройте созданный service account → **Keys → Add key → Create new key → JSON**. Скачается файл.
5. Положите его в проект как `secrets/service_account.json` (папка `secrets/` в git не попадает).
6. Скопируйте email service account (вида `...@...iam.gserviceaccount.com`) — он нужен на следующем шаге.

### 4. Таблица

1. **Важно:** ваша ссылка ведет на файл Excel (.xlsx), открытый в Google Таблицах. API с таким файлом
   не работает. Откройте его и выберите **Файл → Сохранить как Google Таблицу** — появится копия
   в формате Google Sheets. Дальше работайте с ней.
2. В новой таблице **Настройки доступа** → добавьте email service account с ролью **Редактор**.
3. ID таблицы — часть адреса между `/d/` и `/edit`:
   `https://docs.google.com/spreadsheets/d/`**`1AbC...xyz`**`/edit` → это `SPREADSHEET_ID`.

### 5. Настройки

```bash
cp .env.example .env
```

Заполните в `.env`: `BOT_TOKEN`, `ALLOWED_USER_IDS`, `SPREADSHEET_ID`; при желании `CURRENCY`
(например `₽` или `€`, по умолчанию без символа), `TIMEZONE` (по умолчанию `Europe/Moscow`),
`REPORT_HOUR` (по умолчанию 10).

### 6. Запуск на сервере

Нужны Docker и Docker Compose. Скопируйте папку проекта на сервер (вместе с `.env` и
`secrets/service_account.json`) и выполните в ней:

```bash
docker compose up -d --build
```

Проверить логи:

```bash
docker compose logs -f bot
```

В логе должно быть `Бот запущен`, а в таблице — новые листы. Напишите боту `/start`.

Обновление после изменений кода: `git pull` (или копирование файлов) и снова `docker compose up -d --build`.
Остановить: `docker compose down`.

## Импорт истории из листа «Бюджет» (одноразово)

Переносит месячные итоги по категориям из старого листа «Бюджет» в «Операции»: одна операция
на каждую категорию бота за месяц (старые категории, попавшие в одну категорию бота, складываются),
дата — последний день месяца, счет «Карта», тег `#импорт`, комментарий «импорт из Бюджета». Текущий месяц не импортируется. Сам лист «Бюджет» не меняется.

```bash
docker compose run --rm bot python -m bot.import_budget            # dry-run: только показать
docker compose run --rm bot python -m bot.import_budget --apply    # записать
```

- Суммы категорий сверяются с «Доходы за месяц» / «Расходы за месяц»; месяц с расхождением
  не записывается (`--force` — записать все равно).
- Старые названия сопоставляются с категориями бота («ЖКУ + интернет» → ЖКУ,
  «Транспорт/РЖД/Такси» → Транспорт/РЖД, «Еда вне дома/доставки» → Еда вне дома, «Связь» → Подписки и т.п.).
  Несопоставленные выводятся предупреждением; указать вручную: `--map "Старое=Новое"`.
- Повторный запуск пропускает уже импортированные месяцы; `--replace` перезаписывает их.
- После записи в боте: `/refresh`, затем `/report`.

## Локальная разработка

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements-dev.txt
.venv/bin/python -m pytest
```

Пробный запуск без Google Таблицы (данные в памяти, пропадут при перезапуске): в `.env` поставьте
`STORAGE=memory`, затем `.venv/bin/python -m bot`.

## Устройство кода

```
bot/
  __main__.py      запуск: конфиг, хранилище, aiogram, планировщик, меню команд
  config.py        переменные окружения
  parser.py        разбор «350 кофе», дат, тегов, счетов, переводов
  categories.py    категории по умолчанию и угадывание по ключевым словам
  reports.py       расчеты и тексты отчетов: без тяжелых трат, итоги месяца, /stats, капитал, сигналы
  trips.py         командировки: разбор /trip, траты поездки, /trips
  charts.py        картинка для /stats (matplotlib)
  service.py       бизнес-логика без Telegram: запись, отмена, обучение, остатки, поездки
  storage.py       Google Sheets (gspread) с кэшем + хранилище в памяти для тестов
  handlers.py      команды, сообщения и кнопки aiogram, белый список пользователей
  notify.py        отправка итогов месяца, /stats и сигналов
  scheduler.py     1 числа — опрос остатков и итоги, вечером — сигналы
  state.py         небольшое состояние в data/state.json
  import_budget.py одноразовый импорт истории из листа «Бюджет»
tests/             pytest: парсер, отчеты, сервис, кнопки, таблица (поддельный gspread)
```
